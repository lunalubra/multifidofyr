This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing site for **Multifido Fisioterapia & Readaptacion**, a clinic in Leganes (Madrid). Next.js 16 App Router + React 19 + Prismic CMS, content in Spanish (`lang="es-es"`). Repo started from the `nextjs-starter-prismic-minimal` template — the README is mostly unmodified template text; this file is the real source of truth.

## Commands

```sh
npm run dev          # Next dev + Slice Machine concurrently (named "next" / "slicemachine")
npm run next:dev     # Next dev only
npm run slicemachine # Slice Machine only (http://localhost:9999)
npm run build        # next build
npm run start        # next start
npm run lint         # eslint . (eslint-config-next, core-web-vitals + typescript)
npm run format       # prettier --write .

# Seed/update Prismic documents — all require PRISMIC_WRITE_TOKEN
PRISMIC_WRITE_TOKEN=<token> npm run migrate         # seeds "home" page (all slices)
PRISMIC_WRITE_TOKEN=<token> npm run migrate:legal   # seeds legal pages
PRISMIC_WRITE_TOKEN=<token> npm run migrate:blog    # seeds blog posts
```

There is no test runner configured.

## Architecture

### Content flow: Prismic → Slice Machine → Slice Zone

Pages are documents in Prismic composed of an ordered list of **Slices**. Each slice has a model (`customtypes/*/index.json` + `src/slices/*/model.json`) and a React component (`src/slices/*/index.tsx`). The flow:

1. A route (`src/app/page.tsx`, `src/app/[uid]/page.tsx`, `src/app/blog/[uid]/page.tsx`) fetches a document with `createClient().getByUID(...)`.
2. `<SliceZone slices={doc.data.slices} components={components} />` renders the doc's slice array using the map in `src/slices/index.ts` (generated by Slice Machine — **do not edit**, regenerate via the Slice Machine UI).
3. Slice components receive props typed by `prismicio-types.d.ts` (also generated — **do not edit**).

Adding a new slice means: create/edit the model in Slice Machine (which writes to `src/slices/<Name>/`), push it to Prismic, regenerate types, then implement `index.tsx`. Slice Machine also updates `src/slices/index.ts` and the `choices` block in `customtypes/page/index.json`.

### Routing

URL mapping is centralized in `src/prismicio.ts`:

```ts
const routes: Route[] = [
  { type: "page", uid: "home", path: "/" },
  { type: "blog_post", path: "/blog/:uid" }
];
```

- `/` → `page` doc with UID `home` (`src/app/page.tsx`)
- `/:uid` → any other `page` doc (`src/app/[uid]/page.tsx` — `generateStaticParams` explicitly filters out `home`)
- `/blog` → static listing fetched via `getAllByType("blog_post")` ordered by `publication_date desc`
- `/blog/:uid` → `blog_post` doc

The blog routes use `"blog_post" as any` casts and silently swallow errors so the build does not fail when the `blog_post` type has not been pushed to Prismic yet — keep that guard if you touch those files.

### Caching & preview

`createClient()` in `src/prismicio.ts` configures Next fetch options based on `NODE_ENV`:
- **production**: `cache: "force-cache"` with tag `"prismic"`.
- **dev**: `next: { revalidate: 5 }`.

Three API routes manage the Prismic integration — keep them as-is:
- `src/app/api/preview/route.ts` — entry point for Prismic Page Builder previews.
- `src/app/api/exit-preview/route.ts` — exits a preview session.
- `src/app/api/revalidate/route.ts` — `POST` from Prismic webhook calls `revalidateTag("prismic", "max")` to purge the cache on publish.

`enableAutoPreviews({ client })` is called inside `createClient`, and `<PrismicPreview>` is mounted in `src/app/layout.tsx`.

### Custom types

- `page` (`customtypes/page/index.json`): UID + title + slice zone (lists every available slice in `choices`) + SEO fields. Slice Machine maintains the `choices` list — adding a new slice without registering it here means it cannot be added to a page in the Page Builder.
- `blog_post` (`customtypes/blog_post/index.json`): UID, title, featured_image, excerpt, category, publication_date, author, rich-text-only slice zone, SEO fields.

### Styling system

Global design tokens live in `src/app/globals.css` (CSS custom properties): Radix Colors palettes (grass/olive/sand/red/alpha), 4px-base spacing scale, fluid type scale via `clamp()`, warm "premium" surfaces, shadows, radii, easings, durations. Per-component styles are CSS Modules colocated with each component/slice (`*.module.css`). Fonts (Playfair Display headings, Inter body) are loaded via `next/font/google` in `src/app/layout.tsx` and exposed as `--font-playfair` / `--font-inter`.

Reveal animations are handled by `src/hooks/useScrollReveal.ts` (`useScrollReveal` and `useStaggerReveal`) — IntersectionObserver-based, and they short-circuit when `prefers-reduced-motion: reduce` matches. Any new scroll-triggered animation should go through these hooks rather than inlining IntersectionObservers.

Many slices are `"use client"` because they use these hooks or scroll listeners (e.g. HeroSection parallax). Convert to a server component only if it has no client-side effect.

### Migration scripts

`scripts/migrate*.ts` use `@prismicio/client`'s `createWriteClient` + `createMigration`. They are idempotent: each script fetches the document by UID first, and either updates in place or creates a new one. Rich-text helpers (`h1`, `h2`, `p`, `li`, …) at the top of each script construct the structured-text JSON Prismic expects. The seeded content (home page copy, legal text, blog posts) is duplicated inline in these scripts — they are the source of truth for that content until it has been edited in Prismic.

## Conventions

- Path alias `@/*` → `./src/*` (configured in `tsconfig.json`).
- `slicemachine.config.json` pins `repositoryName: "multifidofyr"`. `NEXT_PUBLIC_PRISMIC_ENVIRONMENT` overrides it at runtime (used for sandbox environments).
- Content/UI copy is Spanish without accents in many places (e.g. "Quienes Somos", "Fisioterapia & Readaptacion") — match the existing style when adding copy.
- Don't hand-edit generated files: `prismicio-types.d.ts`, `src/slices/index.ts`, anything under `.slicemachine/` or `.next/`.
